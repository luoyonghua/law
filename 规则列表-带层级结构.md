
# 规则层级结构接口说明

## 新增接口：获取完整层级结构

### 接口信息

- **请求路径**：`/api/rules/hierarchy`
- **请求方法**：GET
- **接口说明**：一次性返回规则的完整层级结构，包含所有一级模块、二级模块和规则详情
  - 不传参数时：返回所有文书类型的完整层级数据
  - 传入 `doc_type` 参数时：返回指定文书类型的层级数据

### 请求参数

| 参数名   | 类型   | 必填 | 说明                                                         |
| -------- | ------ | ---- | ------------------------------------------------------------ |
| doc_type | string | 否   | 文书类型（如：判决书、审查逮捕报告等）。不传则返回所有文书类型 |

### 请求示例

```bash
# 获取所有文书类型的层级数据
GET /api/rules/hierarchy

# 获取指定文书类型的层级数据
GET /api/rules/hierarchy?doc_type=判决书
```

## 使用场景

### 场景1：页面初始化，显示所有文书类型

前端页面加载时，调用不带参数的接口，一次性获取所有文书类型的层级数据并缓存：

```javascript
// 页面加载时
async function loadAllHierarchyData() {
    const response = await fetch('/api/rules/hierarchy');
    const data = await response.json();
    
    if (data.success) {
        // 缓存所有数据
        allDocumentsData = data.data;
        console.log('加载成功:', data.data.total_document_types, '种文书类型');
    }
}
```

### 场景2：用户选择特定文书类型

用户从下拉框选择特定文书类型时，从已缓存的数据中筛选显示：

```javascript
function loadRules() {
    const docType = document.getElementById('docTypeFilter').value;
    
    if (!docType) {
        // 显示所有文书类型
        displayAllDocumentTypes();
    } else {
        // 从缓存中查找对应的文书类型
        const docData = allDocumentsData.all_documents.find(
            doc => doc.document_type === docType
        );
        displaySingleDocType(docData);
    }
}
```

### 场景3：按需加载单个文书类型

如果只需要某个特定文书类型的数据，可以直接请求：

```javascript
async function loadSingleDocType(docType) {
    const response = await fetch(`/api/rules/hierarchy?doc_type=${docType}`);
    const data = await response.json();
    
    if (data.success) {
        displaySingleDocType(data.data);
    }
}
```

## 性能优势

### 传统方式（多次请求）

```
页面加载 → 选择文书类型1 → 请求接口 → 等待响应 → 显示
         → 选择文书类型2 → 请求接口 → 等待响应 → 显示
         → 选择文书类型3 → 请求接口 → 等待响应 → 显示
```

**问题**：每次切换都需要等待网络请求

### 新方式（一次请求）

```
页面加载 → 请求所有数据 → 缓存
         → 选择文书类型1 → 从缓存筛选 → 立即显示
         → 选择文书类型2 → 从缓存筛选 → 立即显示
         → 选择文书类型3 → 从缓存筛选 → 立即显示
```

**优势**：

- ✅ 减少网络请求次数（从 N 次减少到 1 次）
- ✅ 切换文书类型瞬间响应（无需等待）
- ✅ 减轻服务器压力
- ✅ 提升用户体验

## 注意事项

1. **缓存策略**：前端应该缓存获取的数据，避免重复请求
2. **数据更新**：如果规则库有更新，需要重新调用接口刷新缓存
3. **内存占用**：一次性加载所有数据约 1.2MB，对现代浏览器影响很小
4. **网络环境**：在网络较慢的环境下，首次加载可能需要几秒钟
5. **降级方案**：如果一次性加载失败，可以降级为按需加载单个文书类型
